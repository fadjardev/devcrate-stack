# Audit devcrate — implementasi, fitur, dan dashboard (2026-11-12)

Audit atas biner `devcrate` 0.3.0 di cabang `dev` (`4c00e99`), dalam dua bagian:
inti dan subcommand (Bagian A), lalu dashboard (Bagian B). Bagian C mencatat apa
yang diubah pada dashboard dalam pekerjaan yang sama. Temuan Bagian A yang serius dan
yang gagal pada kasus umum (A1–A8) sudah diperbaiki 2026-11-13 (lihat kolom Status);
yang kecil belum; di Bagian B, yang
sudah diperbaiki hanya yang ditandai demikian.

## Ringkasan

- Build bersih, 213 test lulus (209 sebelum pekerjaan ini), 1 di-ignore.
- Empat temuan bisa menghilangkan data atau mematikan proses yang bukan urusan
  devcrate (A1–A4). Dua di antaranya terbukti lewat reproduksi.
- Empat alur gagal pada kasus yang umum (A5–A8).
- Dashboard: delapan masalah tampilan diperbaiki bersama desain ulangnya, sebelas
  masalah perilaku masih terbuka.

## Bagian A — inti dan subcommand

### Serius

| # | Masalah | Lokasi | Status |
| --- | --- | --- | --- |
| A1 | `site add <host> --path <luar>` menghapus rekursif `projects\<host>` bila sudah ada sebagai folder asli, lalu menggantinya dengan junction. Exit 0, tanpa peringatan | `site.rs:271-275` | terbukti; **diperbaiki** 2026-11-13 |
| A2 | `devcrate stop` dan `restart` mematikan semua proses yang berjalan dari `node\` dan `bun\`, bukan hanya dev server yang dimulai devcrate | `config.rs:370-390`, `control.rs:86` | terbukti; **diperbaiki** 2026-11-13 |
| A3 | File hosts dibaca dengan `unwrap_or_default()`. Bila gagal dibaca (bukan UTF-8, terkunci), isinya dianggap kosong dan seluruh file ditimpa hanya dengan blok devcrate | `hosts.rs:222`, `hosts.rs:247` | dari kode; **diperbaiki** 2026-11-13 |
| A4 | `install php <versi> --force` membuang `php.ini` lama beserta blok devcrate dan DLL PECL di `ext\`. `php.ini` hanya dipertahankan untuk folder yang isinya cuma `php.ini` | `install/mod.rs:855` | dari kode; **diperbaiki** 2026-11-13 |

**A1.** Urutannya: `--path` menunjuk folder di luar `projects\`, sehingga devcrate
perlu junction `projects\<host>`. Bila nama itu sudah dipakai, kodenya memanggil
`remove_file` lalu `remove_dir_all` tanpa memeriksa apakah itu junction atau folder
berisi. Reproduksi: `projects\shop.test\important.txt` hilang setelah
`site add shop.test --path <lain>`. Ini bertentangan dengan janji di roadmap bahwa
folder proyek tidak pernah dihapus.

*Perbaikan (2026-11-13):* hanya junction yang boleh diganti. Folder atau file asli
dengan nama itu ditolak, `--force` pun tidak menembusnya, sebelum conf, sertifikat,
atau hosts disentuh. Diuji oleh `a_real_project_folder_is_never_replaced_by_a_junction`
dan direproduksi ulang dengan biner: exit 1, `important.txt` tetap ada.

**A2.** Node.js dan Bun didaftarkan sebagai `ServiceKind` dengan `process_prefix`
seluruh folder `node\` / `bun\` dan masa tunggu nol, jadi `stop` langsung
men-terminate apa pun yang berjalan dari sana. Reproduksi: proses yang dijalankan
dari `node\v99.0.0\node.exe` dilaporkan `terminated (1 process(es))`. Terminal lain
yang menjalankan `npm run dev`, atau tool apa pun yang berjalan di atas Node milik
stack, ikut mati. Dev server milik devcrate sendiri sudah ditangani terpisah oleh
`devserver::stop_all`, jadi entri layanan ini tidak diperlukan untuk itu. Dari
dashboard, satu tombol `x` di baris Node.js melakukan hal yang sama.

*Perbaikan (2026-11-13):* `stop_service` tidak lagi men-terminate apa pun untuk
Node.js dan Bun; hasilnya `Stopped::LeftAlone(n)`, ditampilkan sebagai `left running
(n process(es) not started by devcrate; ...)`, dan bukan kegagalan. Berlaku untuk
`stop`, `restart`, dan `x`/`X`/`t`/`T` di dashboard. Diuji oleh
`stopping_node_leaves_processes_running_from_it_alone`. Direproduksi ulang di stack
tiruan: biner lama `terminated (1 process(es))`, biner baru membiarkan proses hidup.

**A3.** Terkait: `hosts.bak` tidak pernah terbuat tanpa hak Administrator, karena
kegagalan copy diabaikan (`hosts.rs:54`) dan jalur elevasi hanya menyalin isi baru.
Hasil `copy` yang dielevasi juga tidak diperiksa — UAC yang disetujui tetapi copy
yang gagal tetap dilaporkan `Updated`.

*Perbaikan (2026-11-13):* `read_hosts` hanya menganggap file *tidak ada* sebagai
kosong; gagal baca lain menjadi error, dan file tidak disentuh. Copy yang dielevasi
kini membuat `hosts.bak` dulu bila belum ada, dan hasilnya dinilai dengan membaca
ulang file hosts, bukan dari exit code PowerShell. Bagian baca diuji oleh
`an_unreadable_hosts_file_is_an_error_not_an_empty_one`; jalur UAC belum dijalankan
(butuh prompt sungguhan).

**A4.** `docs/cli.md` menyebut versi lama "dipindahkan, bukan dihapus"; itu hanya
benar selama swap. Setelah swap berhasil folder lama dihapus, dan `keep` kosong
kecuali untuk folder yang hanya berisi `php.ini`. Ini jalur yang dipakai untuk
menaikkan patch PHP, jadi efeknya bukan kasus pinggiran.

*Perbaikan (2026-11-13):* `php.ini` lama kini selalu dipertahankan lewat
`swap_keeping`, dan `carry_extensions` menyalin ke staging setiap file di direktori
ekstensi lama (yang ditunjuk `extension_dir`) yang tidak dibawa build baru.
Penyalinan terjadi sebelum swap, jadi kegagalan tidak mengubah apa pun. DLL yang
dibawa build baru tidak ditimpa. Output menyebut `php.ini kept from the replaced
installation` dan daftar yang dibawa. Diuji end-to-end lewat zip PHP tiruan oleh
`a_forced_php_reinstall_keeps_php_ini_and_pecl_dlls`. Batasnya: file lain di luar
direktori ekstensi (DLL di samping `php.exe`, `cacert.pem`) tidak dibawa, dan ini
tertulis di `docs/cli.md`.

### Fitur yang gagal pada kasus umum

| # | Masalah | Lokasi | Status |
| --- | --- | --- | --- |
| A5 | Deteksi PHP dari `composer.json` mengambil angka pertama constraint dan menuntut versi itu terpasang persis. `"php": "^8.2"` dengan hanya 8.5 terpasang menghasilkan `PHP 8.2 is not installed` | `site.rs:156-175`, `site.rs:245-249` | terbukti; **diperbaiki** 2026-11-13 |
| A6 | Dengan `--no-tls`, tanpa mkcert, atau saat penerbitan gagal, conf tetap berisi `listen 443 ssl` yang menunjuk `_wildcard.test.pem` — file yang tidak lagi dibuat | `site.rs:298-303`, `mkcert.rs:99` | conf terbukti ditulis; dampak ke nginx dari kode; **diperbaiki** 2026-11-13 |
| A7 | `auto_renew` saat `start` menilai vhost yang sengaja memakai sertifikat CA lain sebagai "foreign CA", lalu menulis ulang baris `ssl_certificate`-nya ke sertifikat mkcert. Aktif secara default | `cert.rs:150`, `cert.rs:254-261` | dari kode, lalu terbukti; **diperbaiki** 2026-11-13 |
| A8 | Bila perintah shutdown MariaDB gagal (misalnya root diberi password), devcrate tetap menunggu 30 detik penuh sebelum mematikan paksa | `control.rs:261-266` | dari kode, lalu terbukti; **diperbaiki** 2026-11-13 |

**A5** mengenai `site add` dan auto-vhost sekaligus, dan `setup` hanya memasang
PHP terbaru — jadi proyek Laravel hasil clone gagal dilayani di stack baru.

*Perbaikan A5 (2026-11-13):* modul baru `composer_php` membaca constraint Composer
(`^`, `~`, `>=`, `>`, `<=`, `<`, `!=`, wildcard, rentang tanda hubung, `||`, AND
dengan spasi atau koma) dan menjawab apakah suatu rilis PHP X.Y diizinkan. `site
add` dan auto-vhost memakai versi CLI bila memenuhi, kalau tidak versi terpasang
terbaru yang memenuhi. Bila tidak ada, error menyebut constraint, versi terpasang,
dan versi PHP yang perlu dipasang. Constraint yang tak terbaca jatuh ke versi
default. Diuji di `composer_php::tests` dan
`composer_constraints_pick_an_installed_php_that_satisfies_them`, dan direproduksi
ulang dengan biner: `^8.2` dengan hanya 8.5 terpasang kini dilayani PHP 8.5.
**A6**: nginx memuat semua conf di `sites\` sebagai satu dokumen, sehingga satu conf
yang menunjuk sertifikat tak ada menggagalkan seluruh konfigurasi, bukan hanya
situs itu.

*Perbaikan A6 (2026-11-13):* tanpa sertifikat, conf ditulis sebagai HTTP biasa:
hanya `listen 80`, tanpa redirect, tanpa `ssl_certificate`, dan tanpa `HTTPS on`.
`Created` kini membawa `cert_name: Option` beserta alasannya (`--no-tls`, mkcert
tidak ada, atau error mkcert yang sebelumnya ditelan `.ok()`), dan output
menyebut `http://<host>`. Konversi `set-proxy`/`set-php` mempertahankan situs
polos tetap polos. Diuji oleh `without_a_certificate_the_conf_is_plain_http`.
Dampak ke nginx kini *terbukti*: dengan nginx stack sendiri, conf dari biner lama
gagal `nginx -t` (`cannot load certificate ... _wildcard.test.pem`), sedangkan conf
dari biner baru lolos.

*Perbaikan A7 (2026-11-13):* `renew_needed` (dipakai `start` dan `cert renew`
tanpa nama) kini hanya memperbarui sertifikat yang memang urusan devcrate: yang
bernama `_wildcard.<domain>.pem` (termasuk dari CA mkcert mesin lain, yaitu stack
yang disalin), yang diterbitkan CA mkcert mesin ini, atau yang hilang. Sertifikat
dari CA lain dengan nama sendiri, kedaluwarsa atau tidak, dan yang tak terbaca,
dibiarkan dan dicatat di baris `left`. `cert renew <host>` dan `--all` tetap
menggantinya. `SiteCert` mendapat `issued_here`, karena keadaan `Expired`
dinilai sebelum penerbit dan dulu menyembunyikan sertifikat asing yang
kedaluwarsa. Diuji oleh `an_unasked_renewal_leaves_another_cas_certificate_alone`.
Direproduksi dengan mkcert sungguhan di stack tiruan: biner lama menulis ulang
`certs/company.pem` menjadi `_wildcard.db.test.pem`, biner baru membiarkannya
tetapi tetap memperbarui `_wildcard.shop.test.pem` dari CA asing. Ditemukan sambil
lalu: dua test di `cert.rs` berbagi satu file fixture dan bisa saling menghapus
saat berjalan paralel; kini tiap test punya filenya sendiri.

*Perbaikan A8 (2026-11-13):* bila perintah shutdown gagal, `stop_service` hanya
memberi `FAILED_ASK_GRACE` (2 detik) alih-alih masa tunggu penuh, karena tidak ada
yang sedang mematikan diri. Berlaku untuk semua layanan yang punya perintah
shutdown. Diuji oleh `a_failed_shutdown_command_does_not_wait_out_the_grace`:
salinan `ping.exe` sebagai `mariadbd.exe` dan salinan `hostname.exe` yang langsung
gagal sebagai `mariadb-admin.exe`. Dengan perbaikan, test selesai dalam ~2,7 detik;
dengan masa tunggu lama, test gagal setelah 30,5 detik.

*Catatan lanjutan A8 (2026-11-13):* test itu kemudian gagal sesekali dengan ~30
detik bahkan setelah perbaikan. Pengukuran per langkah menunjukkan sebabnya bukan
logika stop: satu kali scan tabel proses (`ProcessTable::scan`) kadang tertahan
puluhan detik saat mesin ini berjalan dengan CPU 100% (361 proses). Keputusan
lama tunggu kini ada di fungsi murni `patience()` dan diuji tanpa jam dinding.
Test end-to-end tetap memeriksa bahwa perintah gagal berujung terminate dengan
alasannya, tetapi tidak lagi mengukur waktu.

### Yang sudah kokoh

- Ekstraksi zip menolak path absolut, drive letter, `..`, dan titik dua.
- Unduhan ditulis ke `.part`, di-hash sambil mengalir, dan baru diberi nama akhir
  setelah lolos; perbedaan "terverifikasi" dan "hanya TLS" ada di tipe data.
- Staging dan swap membuat instalasi setengah jadi tidak pernah terlihat.
- Nama database dibatasi ke `[A-Za-z0-9_-]` sebelum masuk ke SQL.
- PATH pengguna ditulis dengan tipe registry yang dipertahankan.
- Skrip PowerShell dikirim lewat `-EncodedCommand`.
- Dev server dikenali lewat PID plus waktu mulai, bukan PID saja.
- `php.ini` diedit lewat file sementara dan rename, dan gagal baca tidak pernah
  berujung penimpaan (kebalikan dari A3).

## Bagian C — perubahan pada dashboard

Hanya lapisan gambar yang diubah (`tui/view.rs`, dan `tui/theme.rs` yang baru),
plus profil Windows Terminal di `integration.rs`. `app.rs` dan `worker.rs` tidak disentuh: tombol, alur, dan job
sama persis.

### Layout

Rujukannya contoh aplikasi ratatui sendiri (<https://ratatui.rs/examples/apps/>):
`demo2` untuk panel tanpa garis, bar satu baris, dan scrollbar hanya-thumb;
`table` untuk tabel bergaris selang-seling dan palet Tailwind; `popup` untuk
`Clear` di bawah popup.

- **Panel, bukan kotak.** Tiap pane adalah blok dengan latarnya sendiri, satu
  kolom dari tepi layar, namanya di baris pertama. Garis hanya dipakai bila
  bermakna: tepi kiri kartu, bingkai popup.
- **Dua bar satu baris di atas**: nama dan versi di kiri, ringkasan stack, CLI PHP,
  dan root di kanan; di bawahnya tab, dengan tab aktif berwarna panel sehingga
  menyatu dengan pane yang dinamainya.
- **Tabel bergaris selang-seling**, baris terpilih berupa bar bernuansa indigo
  dengan tepi `▌`, dan scrollbar hanya-thumb yang muncul bila baris tidak muat.
- **Kartu ringkasan** (STACK, SITES, CERTIFICATES, COMMAND LINE) di atas tab,
  pada terminal setinggi 28 baris atau lebih. Tepi kirinya tebal, berwarna sesuai
  yang dilaporkannya.
- **Panel detail** di samping tabel Services dan Sites, pada terminal selebar 118
  kolom atau lebih: port satu per baris berikut siapa yang memegangnya, PID, path;
  untuk situs: URL, yang melayaninya, keadaan dan kedaluwarsa sertifikat, dev
  server. Diakhiri tombol yang relevan untuk keadaan baris itu.
- **Footer adaptif**: baris status di atas bar tombol; tiap tombol di blok kecilnya
  sendiri. Petunjuk tombol gugur dari belakang bila tidak muat;
  `? help` dan `q quit` selalu bertahan. Progres yang menyebut persen digambar
  sebagai bar.
- **Daftar tombol dua kolom**, muat di terminal 20 baris.
- **Popup** punya latar sendiri, menyebut tombolnya di tepi bawah, dan bingkai
  hasil berwarna hijau atau merah sesuai hasilnya.

Di terminal kecil (96×22, ukuran yang dipakai test) tidak ada yang hilang
dibanding sebelumnya: kartu dan panel detail hanya muncul bila ada ruang.

### Teks

Judul dan petunjuk ditulis ulang supaya mengatakan apa yang terjadi, bukan menamai
widget: "Install a service or runtime", "Which PHP should the command line run?",
"Nothing is served yet." berikut dua tombol untuk memulainya, dan petunjuk di
panel detail seperti "It went down on its own. s starts it again; 3 has its log."
Frasa yang dikunci oleh test dan dokumentasi dipertahankan.

### Font JetBrains Mono

Sebuah program TUI tidak bisa memilih font: ia hanya mengirim karakter, dan
terminal yang menentukan rupanya. Satu-satunya tempat devcrate bisa memintanya
adalah **profil Windows Terminal** yang ditulis `devcrate setup`. Profil itu
sekarang:

- menamai JetBrains Mono sebagai font bila salah satu keluarganya terpasang —
  `JetBrains Mono`, atau build Nerd Font seperti `JetBrainsMono NFM`. Di mesin ini
  yang terdeteksi adalah `JetBrainsMono NFM`;
- tidak menamai font apa pun bila tidak ada yang terpasang, karena profil yang
  menunjuk font tak ada akan dibuka dengan peringatan;
- membawa skema warna `Devcrate` yang latarnya sama dengan dashboard.

Di root `E:\dev` profil itu belum ada (`devcrate-setup.json` tidak mencatat
shortcut). Menjalankan `devcrate setup` akan membuatnya, bersama shortcut Start
Menu dan Desktop; tidak ada yang dipasang ulang bila semuanya sudah ada. Dibuka
lewat terminal lain, dashboard memakai font terminal itu. Tidak ada glyph yang
memerlukan icon font: semuanya box drawing, block element, atau bentuk geometris
biasa.
